# 条件渲染与业务四态

<MentalModel title="条件渲染就是把当前状态映射为 UI">
React 不提供特殊模板指令；使用 JavaScript 的 `if`、early return、三元表达式和 `&&` 即可描述分支。工程重点是先把业务状态建模清楚，再让每个状态映射到唯一、可理解的界面。
</MentalModel>

<Boundary title="&& 的左值会影响输出">
`condition && <View />` 适合明确 boolean 条件。像 `count && <View />` 这样的写法在 `count` 为 `0` 时可能把 `0` 渲染出来；需要布尔语义时显式比较或转换。
</Boundary>

<AntiPattern title="用多个松散 boolean 表达一个互斥状态机">
`isLoading`、`hasError`、`isEmpty` 若能同时为 true，就可能出现不可能状态。复杂场景优先用单一 status/discriminated union 表达状态，再进行 UI 映射。
</AntiPattern>

<Summary>
- 条件渲染使用普通 JavaScript 控制流。
- 先建模状态，再选择语法。
- early return 很适合阻断态。
- 避免能组合出矛盾 UI 的松散 boolean。
</Summary>
