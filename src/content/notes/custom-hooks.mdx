# Custom Hooks：复用状态逻辑，而不是共享 State

Custom Hook 是以 `use` 开头、可以调用其他 Hooks 的函数。它抽取的是状态ful logic；每次调用仍拥有独立的 State 和 Effects。

<MentalModel title="共享配方，不共享实例">两个组件调用同一个 `useOnlineStatus()`，就像各自按同一配方建立订阅；除非 Hook 连接同一个外部 store，否则它们不会自动共享 React State。</MentalModel>

<Experiment title="观察调用独立性">
在中间 Demo 同时挂载多个使用同一 Custom Hook 的消费者，分别触发局部变化。观察 Hook 代码被复用，但每个组件的 State 生命周期仍由自己的 render tree 身份决定。
</Experiment>

<Observation>好的 Custom Hook API 通常描述领域意图，例如 `useChatRoom`，而不是简单包装 `useEffectOnce` 之类试图绕开 React 数据流的工具。</Observation>

<AntiPattern title="把任意 helper 都改成 Hook">不使用 Hooks 的纯函数不需要 `use` 前缀。也不要用 Custom Hook 隐藏错误 Effect；抽象不会修复错误心智模型。</AntiPattern>

<Boundary>Custom Hook 可以封装外部系统同步，但其参数仍是 reactive inputs；调用方需要理解哪些参数变化会导致内部重新同步。</Boundary>

<Summary>
- Custom Hook 复用逻辑。
- 每次调用 State 独立。
- API 应表达领域意图。
- 先保证底层 Effect 正确再抽象。
</Summary>
