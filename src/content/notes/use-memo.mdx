# useMemo 昂贵计算缓存

<MentalModel title="useMemo 缓存计算结果，不是语义保证">
`useMemo(calculate, deps)` 在依赖未变化时复用上次计算结果；依赖变化时重新计算。它主要用于跳过可测量的昂贵计算，或在确有 identity 消费者时稳定派生对象。
</MentalModel>

<Experiment title="比较直接计算与缓存计算">
在中间 Demo 增加计算规模，分别触发会改变计算依赖和仅改变无关 UI 的更新，观察计算次数与耗时。
</Experiment>

<Observation>
廉价计算通常直接执行更清晰。`useMemo` 自身也需要保存缓存并比较依赖；只有计算成本或下游 identity 价值足够高时才值得使用。
</Observation>

<AntiPattern title="用 useMemo 保证程序正确">
React 可以在特定情况下丢弃缓存，因此业务语义不能依赖“这个对象永远是同一个引用”。若需要持久语义，应使用 state/ref 或重新设计数据所有权。
</AntiPattern>

<Boundary title="React Compiler 可自动缓存部分表达式">
Compiler 能在构建期自动 memoize 值和组件，减少机械式 `useMemo`。手工缓存仍可能用于明确的第三方 identity contract、未编译代码或经 Profiler 证实的热点。
</Boundary>

<Summary>
- `useMemo` 是性能优化，不是状态容器。
- 依赖变化就重算；依赖必须完整。
- 先测量昂贵计算，再决定缓存。
- Compiler 环境不要机械保留历史式 memoization。
</Summary>
