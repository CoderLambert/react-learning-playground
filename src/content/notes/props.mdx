# Props 基础与解构

<MentalModel title="Props 是父组件给子组件的一次 render 输入">
Props 表达父 → 子的数据流。子组件可以读取、解构和基于 props 派生值，但不应修改 props 本身；需要改变数据时，应通过事件回调把“发生了什么”通知拥有该数据的组件。
</MentalModel>

### Props

### State
由组件树中的某个位置拥有，可通过更新请求驱动下一次 render。

<Boundary title="默认值只处理 undefined">
解构默认值在属性缺失或值为 `undefined` 时生效；显式传入 `null` 不会触发默认值。展开 props 很方便，但公共组件中过度透传会模糊 API 边界。
</Boundary>

<AntiPattern title="复制 props 到 state 后持续同步">
若一个值能直接从 props 计算，就不要再保存一份 state 并用 Effect 同步。重复数据源会制造过期和冲突；只有确实需要“以 props 初始化后独立演化”的状态才应单独建模。
</AntiPattern>

<Summary>
- Props 是父 → 子的只读 render 输入。
- callback prop 用来把事件向拥有数据的一侧传递。
- 能从 props 派生的值通常直接计算。
- 明确的 props API 比无边界对象展开更可维护。
</Summary>
