# Suspense Boundary：设计 Reveal Sequence

Suspense boundary 定义“哪些 UI 在等待时一起显示 fallback，以及准备好后如何 reveal”。嵌套 boundary 可以让外层骨架先出现，再逐步揭示较慢区域。

<MentalModel title="Boundary 是产品体验边界，不是每个组件一个 loading">把应该一起出现的内容放在同一 boundary；把允许独立等待的较慢区域放进更深 boundary。边界结构直接表达 reveal sequence。</MentalModel>

<Observation>Suspense 的价值不是让请求更快，而是让 React 能协调“等待中的树”与“已提交的 UI”，从而避免手工 loading 状态散落在组件层级中。</Observation>

<AntiPattern title="机械地细分 Boundary">过多细碎 fallback 会产生闪烁和视觉噪声。边界粒度应与设计稿中的 loading/reveal 单元一致。</AntiPattern>

<Boundary>Suspense 本身不定义数据缓存协议。框架/数据层需要提供可与 Suspense 协作的资源；不要把任意 Promise 都假定为生产级 Suspense 数据方案。</Boundary>

<Summary>
- Boundary 定义等待与 reveal 范围
- 嵌套可实现渐进 reveal
- 粒度由 UX 决定
- Suspense 不等于数据缓存层
</Summary>
