# Controlled Form：让 React State 成为字段事实来源

受控表单把 `value`/`checked` 交给 React State，并通过 `onChange` 把用户输入写回 State，因此界面值由 React 数据流决定。

<MentalModel title="value + onChange 是一个字段级闭环">浏览器产生输入事件 → handler 更新 State → React render 新 value → DOM 显示新值。对这个字段而言，React State 是事实来源；controlled/uncontrolled 是字段的 ownership 决策，不是整个 form 的永久二选一标签。</MentalModel>

<Observation>实时联动、条件禁用、即时校验和跨字段计算是 controlled form 的优势；代价是每次输入都会进入 React 更新路径。</Observation>

<AntiPattern title="重复保存可派生校验">不要把 `isValid`、`fullName` 等可从字段 State 计算的值再存一份 State 并用 Effect 同步。</AntiPattern>

<Boundary>不需要实时 React 协调的字段可以让 DOM 持有值，在提交时用 `FormData` 读取。controlled/uncontrolled 是字段级 ownership 决策；一个真实 form 可以同时包含 controlled field、uncontrolled field，并使用 FormData 作为提交边界。当前 Demo 为了展示闭环，把这些字段都交给同一份 React State；这不意味着生产表单必须全部受控。</Boundary>

<Summary>
- State 是受控字段事实来源。
- onChange 闭合数据流。
- 校验优先派生计算。
- 按字段的 ownership 与交互需求选择 controlled 程度。
</Summary>
