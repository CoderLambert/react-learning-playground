# state-reducer.mdx 审核记录

## 当前结论

审核收口完成。Gate A：PASS；Gate B：PASS；Gate C：PASS。

## Correctness / React 19.2

- `useReducer` 的 reducer 必须是纯函数；React Strict Mode 在开发环境会额外调用 reducer/initializer 来帮助暴露 accidental impurity。
- Demo 中时间戳在事件处理阶段生成并通过 action 传入，reducer 只消费 `(state, action)`，不再在 reducer 内部读取当前时间。
- 标题与正文统一使用“状态转换 / reducer 模式”，不再把一般 `useReducer` 使用场景直接称为有限状态机。
- Note 已补充 `dispatch` 的 snapshot 语义：它请求下一次状态更新，不会同步改写当前 render 已读取到的 state。

## Mental model

主模型现在完整对齐：action 描述发生了什么，reducer 从当前 state + action 计算 next state；是否选择 reducer 取决于更新规则是否需要集中表达、审计或测试，而不是 state 是否为对象或字段数量多少。

## Demo ↔ Note

Gate B 已关闭：

- Note 的 Experiment / DemoReference 与真实 Demo action 对齐：`INCREMENT / DECREMENT / SET_STEP / RESET / UNDO`。
- DemoReference 不再要求通过 UI “证明 reducer 无副作用”；纯度明确由 Source/测试与代码约束验证。
- 右侧区域已从“Action 流转审计日志”改为“计数变更历史”，并明确只记录 `INCREMENT / DECREMENT / RESET` 的 count 转换；`SET_STEP` 不写入历史，`UNDO` 会消费历史，因此不再声称它是完整 action trace。
- `dispatchAudited` 已改名为 `dispatchWithTimestamp`，名称与实际职责一致。

## 边界 / 选型

Note 与 Demo 使用同一判断规则：

- 简单、直接的状态更新继续优先 `useState`；
- 多条更新路径共享规则、事件语义值得集中表达，或转换逻辑值得独立测试时考虑 `useReducer`；
- `useReducer` 本身不提供跨组件共享，需要时再与 Context 等机制组合。

## Final status

本课不需要增加 reducer 调用次数 instrumentation 或完整 action logger。当前 Demo 的目标是演示可预测状态转换和部分 count 历史，Note 已严格限制在这些可观察能力内。

官方基线：React `Extracting State Logic into a Reducer`、`useReducer`。
