## 事实与版本边界

React 19.2 下，`lazy(load)` 会把 `load` 的返回 Promise 与解析后的模块结果缓存起来；首次尝试渲染该 lazy component 时才调用 `load`。加载 pending 时组件 suspend，由最近的 Suspense boundary 显示 fallback；如果 Promise rejection，React 会交给最近的 Error Boundary 处理。Note 与 Demo 对这一点表述一致。

“再次打开通常不再经历首次加载”明确归因于同一个 `lazy` 声明及其缓存结果，而不是泛化成浏览器对所有动态 import 都必然永久缓存。

## Mental Model

“lazy 决定代码加载边界，Suspense 决定等待 UI”是有效心智模型；Suspense 不等于请求层，也不会观察普通 Effect 中的 fetch。

## Demo ↔ Note

Demo 在模块顶层定义 `LazyLessonPanel`，人为增加约 900ms loader 延迟，首次点击能够观察 fallback，隐藏后再次显示能观察已加载模块复用。该时间值是教学模拟，不是 React/lazy 的固定时序；Note 只把 Demo 日志与 UI 现象作为可观察证据。
