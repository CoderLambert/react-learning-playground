# component-jsx-pure-render 审核建议

## 结论

审核收口完成。当前 Note 不再把 Demo 描述成真实的 render/commit instrumentation；纯渲染边界也补充了 local mutation 例外。

## Gate A — Correctness：PASS

- `props / state / context` 作为 render 输入、render 保持纯、StrictMode 开发期额外调用纯函数帮助发现非纯逻辑，均与 React 19.2 官方语义一致。
- JSX 被描述为 JavaScript 中的 UI 描述语法而非 HTML 字符串，方向准确。
- purity 边界已明确：禁止修改 render 开始前存在的外部/非局部数据；本次 render 内新创建且未逃逸的局部对象可以进行局部构造或 mutation。
- Event Handler / Effect 的副作用边界保持按因果关系描述，没有把所有副作用机械归类到同一位置。

## Gate B — Demo Contract：PASS

`<DemoReference>` 已收窄为当前 Demo 真正可观察的事实：

- 修改输入后 JSX 输出随当前输入变化；
- Fragment 与表达式插值参与当前 UI 描述；
- “模拟相同输入重复 Render 两次”只比较纯计算结果稳定与非纯计算结果漂移。

Note 已明确说明本 Demo **不测量真实 render/commit 次数**，也不声称观察被丢弃或重试的真实 render。真实 render vs commit instrumentation 留给 `render-commit` 章节。

## Gate C — Mental Model：PASS

学习者能够得到三个关键判断：

- 为什么：React 需要 render 可重复计算，因此组件计算必须保持纯。
- 什么时候用：组件函数负责根据当前输入计算 UI 描述。
- 什么时候不用：用户动作和外部系统同步等副作用不应塞进 render。

## Final status

无需给本 Demo 增加 render counter、commit counter 或其他生命周期 instrumentation。保持“安全模拟非纯计算、不在真实 render 中制造副作用”的设计即可。
