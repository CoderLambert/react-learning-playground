# component-jsx-pure-render 审核建议

## 结论

当前内容方向正确，但 **Gate B（Demo Contract）暂不完全通过**；Gate A 与 Gate C 基本通过。优先级：中。

## Gate A — Correctness：PASS

- `props / state / context` 作为 render 输入、render 保持纯、StrictMode 开发期额外调用纯函数帮助发现非纯逻辑，均与 React 19.2 官方语义一致。
- JSX 被描述为 JavaScript 中的 UI 描述语法而非 HTML 字符串，方向准确。
- 已修正 Demo 中“网络请求等副作用应放 Event Handler”的过度归类：现在按因果区分 Event Handler、Effect，并明确数据获取还受 framework/data layer 边界影响。

仍建议补一个重要边界：**render 中禁止修改 render 之前已存在的外部对象，但允许对本次 render 内新创建、尚未逃逸的局部对象做 local mutation**。否则初学者可能误解成“render 中任何 mutation 都非法”。

## Gate B — Demo Contract：PARTIAL

Note 的 `<Experiment>` 与 Demo 两个实验基本一致：输入变化、Fragment/表达式、纯计算与非纯计算都能观察。

但 `<DemoReference>` 声称可以“区分组件函数执行、返回 JSX 与最终 DOM 更新”。当前 Demo 没有真实 instrumentation 来显示：

- 组件函数实际执行次数；
- render 次数与 commit/DOM mutation 次数的差异；
- 哪一次 render 被丢弃或重试。

实验 2 已明确写成“模拟重复 render”，这是正确的安全教学做法，因此建议把 Note 的 observe 收窄为 Demo 真正可观察的事实，不要暗示它测量了真实 React render/commit 生命周期。真实 render vs commit 留给 `render-commit` 章节。

## Gate C — Mental Model：PASS

学习者能够得到三个关键判断：

- 为什么：React 需要 render 可重复计算，因此组件计算必须保持纯。
- 什么时候用：组件函数负责根据当前输入计算 UI 描述。
- 什么时候不用：用户动作和外部系统同步等副作用不应塞进 render。

## 内容结构与易懂性

整体不需要继续模板化。当前 `MentalModel → Experiment → Flow → Observation → Boundary → AntiPattern` 已略有卡片密度，但尚未影响理解。后续重写时可把 JSX/Fragment 的普通解释改为连续正文，只保留 MentalModel、Experiment、Boundary 作为强调块。

## 建议改动

1. 收窄 `DemoReference.observe`，只写当前 Demo 确实能观察的现象。
2. 在 purity 边界补充 local mutation 例外，并说明“外部世界/预先存在对象”才是危险边界。
3. 不要在本篇继续展开 render/commit instrumentation；链接到 `render-commit` 即可。
4. 保持“模拟非纯计算而不真的在 React render 中制造副作用”的设计，这一点是正确的。
