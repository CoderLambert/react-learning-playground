## Correctness / React 19.2

- `useRef` 在后续 render 中返回同一个 ref 对象；修改 `ref.current` 不会请求 React 重新 render。
- DOM ref 在对应节点提交后由 React 写入，在节点移除时恢复为 `null`。
- React 官方规则是**通常不要在 render 中读写 `ref.current`**，但存在确定性初始化的窄例外，例如仅当 `ref.current === null` 时创建并保存同一个对象。课程现在明确保留这个例外，不再使用“只能在事件/Effect 中操作”的误导性绝对表述。
- `setInterval` 不提供高精度计时保证。Demo 已从“高精度秒表”改为普通计时器句柄示例，并明确它只用于说明 ref 持有外部句柄。
- 课程不再使用模糊的“Concurrent Mode”作为理由；核心理由是 render 必须可预测且保持纯，React 可以重复调用组件函数来检测或执行渲染工作。

## Mental model

“State 是渲染输入；Ref 是 React 保留但不会纳入更新调度的可变容器”是可靠主线。进一步的生产规则是：**影响 JSX → State；不参与 JSX、但需要跨 render 保存 → Ref；需要连接 DOM/浏览器/第三方命令式 API → Ref + 对应事件或 Effect。**

## Demo ↔ Note

当前实验契约一致：

- DOM focus / scroll 是直接可观察的命令式 ref 用法；
- 可见秒数由 State 驱动，interval ID 由 Ref 跨 render 保存；
- Note 不再虚构“Ref 计数按钮”实验，而是明确让学习者从 Source 验证句柄写入不驱动 UI；
- Demo 也明确说明 `setInterval` 不是高精度时钟。

## 缺失边界 / 反例

- Ref 不是“State 的同步版本”；如果值参与渲染，应使用 State。
- 可预测的一次性初始化是 render 中访问 ref 的窄例外，不能扩展成任意 mutable render cache。
- `useLayoutEffect` 只在必须在浏览器 paint 前测量/同步布局时优先使用；普通外部同步通常用 `useEffect`。
