# controlled-form 审核建议

## 当前结论

- Gate A Correctness：**PASS**
- Gate B Demo Contract：**PASS**
- Gate C Mental Model：**PASS**

## 审核要点

Note 与 Demo 对齐良好。`value` / `checked` 由 React State 提供，`onChange` 把用户意图写回 State；Demo 同时覆盖 input、textarea、select、checkbox、radio，并把 `errors` / `isValid` 作为当前字段 State 的派生值，而不是再存第二份同步 State。

提交快照与 reset 都能真实执行，能够证明“同一份字段 State 驱动 UI、校验和提交数据”的闭环。边界也合理：简单、无需实时 React 协调的表单不必全部受控，可以在提交边界使用 FormData。

## 边界与生产决策

- controlled/uncontrolled 应按“谁对这份信息拥有 authority”判断，不是整个表单的永久二元标签；同一表单可以混合策略。
- 每次输入会触发 React 更新，但这本身不是性能问题；只有测量到大子树更新成本后，才需要拆分组件或引入成熟表单方案。
- `useMemo` 并不是简单校验计算的必要条件；当前 Demo 使用它不影响语义，但课程不应让学习者误以为派生校验必须 memoize。

## 建议修改

1. 可在 Note 中补一句“controlled 是字段级 ownership 决策，可与 FormData/非受控字段混用”。
2. 若后续强调性能，使用 Profiler/真实测量，而不是从“每次键入进入 React 更新路径”直接推出需要优化。
3. 当前实验和项目决策规则已经足以支撑课程，不需要额外扩展模板化章节。
